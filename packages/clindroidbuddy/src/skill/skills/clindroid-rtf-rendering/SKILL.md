# Clindroid RTF Rendering (via r2rtf)

**The RTF file is a mandatory part of every TFL deliverable.** Generating the Clindroid ARD JSON (see the `clindroid-ard-json` skill) is not the final step — every TFL program must also render that JSON into an `.rtf` file. **`r2rtf` is the only package permitted for this** (it is a Pharmaverse-standard, verb-based RTF renderer purpose-built for regulatory tables: https://merck.github.io/r2rtf/). Do not use `officer`, `flextable`, `gt`, or hand-written RTF/control-word strings — those are forbidden the same way `admiral`/`rtables`/`tern` are forbidden for the analysis logic itself.

This skill assumes the input is a Clindroid ARD JSON conforming to the `clindroid-ard-json` skill's schema (§3/§4 there) — call that skill first if you have not already produced or read that JSON.

**How every table program renders:** its last line is `render_ard_rtf(json_payload, rtf_path)`, the function defined in the "Shared Helpers" block of the table-generation skills' SKILL.md and copied verbatim into the program with the other helpers (§3). Never build the r2rtf pipeline by hand, and never call `write_rtf()` yourself: `write_rtf()` on anything other than `rtf_encode()` output — a payload list, a data frame — writes a plain-text file that no RTF reader can open, without any error (§4).

## 1. Output File

- **Path:** `tfls/{tfl_id}.rtf` — same directory and `{tfl_id}` stem as the JSON file (`clindroid-ard-json` §1), only the extension differs (e.g. `tfls/table_14_2_01.json` → `tfls/table_14_2_01.rtf`).
- **Source of truth:** The RTF is rendered from **the same payload list that was just written to the JSON** — `json_payload`, whose `rows` is the final ARD data frame — never from a separately built or recomputed table. One object feeds both files, so they cannot disagree, and nothing is read back from disk. Once the structural columns are removed (§2), `rows` is exactly what `rtf_body()` needs.
- **Overwrite Policy:** Same as the JSON file — always overwrite, no version suffixes.

## 2. Field → r2rtf Argument Mapping

In the table below, `ard` is the payload list passed to `render_ard_rtf()`; its fields are the Clindroid ARD JSON fields of the same names.

| Clindroid ARD JSON field | r2rtf call | Notes |
|---|---|---|
| `rows` | `tbl <- as.data.frame(ard$rows)` **minus the structural columns** (next row), then every remaining character column is passed through `rtf_escape()` — the piping "base" object passed through the rest of the chain | `rows` is already the ARD data frame; no `purrr::pmap()`/manual reshaping. `rtf_escape()` — see §7/§8. |
| `rows[].ord_group` | dropped from `tbl` before `rtf_body()` | **Structural key, never rendered** (`clindroid-ard-json` §3). It is in the JSON so the block ordering is stated in the data, not so the renderer sorts by it — the rows already arrive in order. Drop it unconditionally. |
| `rows[].group` | read once to build `border_top_mat` (§9), then dropped from `tbl` before `rtf_body()` | **Structural key, never rendered.** It marks where one analysis item's rows end and the next begin, which is what the per-section top rule in §9 is drawn from. The item's name is already on screen: the R-generation skills put it on a header row of its own (with the item's p-value), so `group` is not passed to `page_by`, which would print the name a second time (§9). |
| `protocol_number` | `rtf_page_header(tbl, text = rtf_escape(ard$protocol_number), text_justification = "l", text_convert = FALSE)` | Displays the protocol number in the page header, repeated on every page. Must be the first call in the pipe chain (before `rtf_title()`). `text_convert = FALSE` — see §6. `rtf_escape()` — see §7/§8. **Do not pass `use_i18n`** — see §8, this project's installed r2rtf version does not expose that argument on `rtf_page_header()` (confirmed via `args(rtf_page_header)`); passing it errors with "unused argument". |
| `tfl_number`, `tfl_title`, `analysis_population` | `rtf_title(tbl, title = paste(rtf_escape(ard$tfl_number), rtf_escape(ard$tfl_title)), subtitle = rtf_escape(ard$analysis_population), text_convert = FALSE)` | The rendered title is `tfl_number` and `tfl_title` joined with a single space (`paste()`'s default separator), each escaped individually before joining. **Use `tfl_number` (e.g. `"Table 14-2.01"`), never `tfl_id` (e.g. `"table_14_2_01"`)** — `tfl_id` is a file-naming slug only (`clindroid-ard-json` §3) and must never appear in the rendered deliverable. `subtitle` carries the population line beneath the title. `text_convert = FALSE` — see §6. `rtf_escape()` — see §7/§8. **Do not pass `use_i18n`** — see §8. |
| `columns` + `big_n` | `rtf_colheader(tbl, colheader = header_str, col_rel_width = w, text_convert = FALSE)` | Build `header_str` as ONE string, columns split by `"|"` (r2rtf's own convention — not a data structure). One header cell per element of `columns`, in `columns` order — and `columns` already has exactly one element per rendered column, the row-label column included (`clindroid-ard-json` §3), so `length(ard$columns)` must equal `ncol(tbl)` once the structural columns are removed. Build each cell from its `columns` element: if the element names a `big_n` key, render it as `"{escaped_group}\\line(N={big_n[[group]]})"`; otherwise use the escaped element as-is (the label column's header, commonly `""`, and any display-only column such as `"p-value"`). The group name is passed through `rtf_escape()` before insertion, but the literal `\\line` wrapper itself must NOT be escaped, since it is r2rtf/RTF raw syntax, not user data. `\\line` in the R string literal encodes a within-cell line break in the rendered RTF — confirmed by direct reproduction, this is the correct RTF control word (not `"\n"`), and it is embedded as raw RTF text so `text_convert = FALSE` does not affect it. `text_convert = FALSE` is required here too — see §6, since `columns` group names commonly contain `_`. `border_left = NULL, border_right = NULL` — no vertical rules, see §9. **Do not pass `use_i18n`** — see §8. |
| `footnotes` | `rtf_footnote(tbl, footnote = footnote_str, text_convert = FALSE)` | Sort by `ord`, format each as `"({label}) {text}"` — the same `(a)` form the table's header and body use to refer to it (`tfl-spec-writer` §3c) — with `label`/`text` each passed through `rtf_escape()` first, join with the literal RTF control word `"\\line"` (NOT a plain `"\n"` — with `text_convert = FALSE` per §6, `rtf_footnote()` no longer converts `"\n"` to a line break, so the line break must be written directly as `\\line`, the same raw-RTF-text mechanism `rtf_colheader()` already relies on). `border_left = NULL, border_right = NULL` — no vertical rules, see §9. **Do not pass `use_i18n`** — see §8. |
| `program_path` | `rtf_source(tbl, source = sprintf("Source: %s", rtf_escape(ard$program_path)), text_justification = "l", text_convert = FALSE)` | Optional but recommended for traceability back to the generating R program. `text_justification = "l"` flushes the source line to the left margin, matching `rtf_page_header()` — see §9. `text_convert = FALSE` — see §6, since file paths commonly contain `_`. `rtf_escape()` — see §7/§8. **Do not pass `use_i18n`** — see §8. |
| — | `rtf_page(tbl, ...)` | Only add this call if the TFL Spec/Shell explicitly requires non-default page orientation or size; otherwise omit and accept r2rtf's defaults. |
| — | `rtf_body(tbl, col_rel_width = w, text_convert = FALSE, text_justification = j, border_left = NULL, border_right = NULL, border_top = border_top_mat, border_first = "single")` | `text_convert = FALSE` — see §6, since row labels and formatted values commonly contain `_` (e.g. variable names, parameter codes). `tbl`'s character columns were already escaped upstream (the `rows` row above) — do not escape a second time. The remaining arguments are this project's table design — see §9 for what each one does and what still needs confirming. **Do not pass `use_i18n`** — see §8. |
| — (final two calls, in this order) | `rtf_encode()` then `write_rtf(rtf, file)` | **See §4 — omitting `rtf_encode()` does not raise an error.** |

`col_rel_width` (an argument on **both** `rtf_colheader()` and `rtf_body()`) must be the same vector in **both** calls, one element per column of `tbl` — r2rtf does not validate this and a mismatch produces a misaligned table with no warning, not an error. This is the reason the structural columns must be dealt with deliberately: `ord_group` and `group` are both dropped, so `ncol(tbl) == length(ard$columns)`. `render_ard_rtf()` checks the relationship and stops instead of trusting it (§3).

## 3. Reference Implementation: `render_ard_rtf()`

The reference implementation is a function, not a code pattern to transcribe: `render_ard_rtf(ard, rtf_path, col_widths = NULL, orientation = "portrait", item_header = TRUE)` in the "Shared Helpers" block (§3) of `r-coder-complex-table`, `clinical-categorical-single-factor` and `clinical-bds-multi-param` (the three copies are identical, enforced by a test). It is copied verbatim into the program with the other helpers, together with `rtf_escape()`, and called once, last, on the payload list just written to the JSON:

```r
jsonlite::write_json(json_payload, sprintf("tfls/%s.json", tfl_id), auto_unbox = TRUE, pretty = TRUE)
render_ard_rtf(json_payload, sprintf("tfls/%s.rtf", tfl_id))
```

What it does, in order, each step for the reason given in the section named:

1. Checks the file names (lowercase, `clindroid-ard-json` §1) and the table's structure: `columns[1]` is not the literal `"label"`, every analysis item starts with its header row (`label` equal to `group`), and p-values sit on header rows only — the shape `continuous_block()`/`categorical_block()` build. Any failure stops the run with the items named.
2. Takes `rows` (the ARD data frame) and drops `ord_group` and `group` from the body, after using `group` to find each analysis item's first row (§2, §9). It stops if the remaining columns do not match `columns` one for one, which would otherwise misalign the table silently (§2).
3. Escapes every character cell and every free-text field with `rtf_escape()` (§7, §8).
4. Builds the column header from `columns`, with `\line(N=xx)` from `big_n` under each treatment group (§2).
5. Calls `rtf_page_header()` → `rtf_title()` → `rtf_colheader()` → `rtf_body()` → `rtf_footnote()` (only when there are footnotes, each printed `(a) text`) → `rtf_source()` → `rtf_encode()` → `write_rtf()`, every text-bearing call with `text_convert = FALSE` (§6) and the design settings of §9.
6. Reads the first bytes of the written file and stops unless they are `{\rtf1` (§4).

`col_widths` (one relative width per element of `columns`) and `orientation` (`"landscape"` only when the TFL Spec or Shell asks for it) are the settings a program may pass, plus `item_header = FALSE` for the one layout without header rows: the user-instructed item-name column. Do not edit the function inside a program; a Shell that needs anything else is a question for the user.

## 4. Critical Pitfall: `rtf_encode()` Before `write_rtf()`

**`write_rtf(rtf, file)` does not error if `rtf_encode()` was skipped — it silently writes a small plain-text dump of the cell values instead of a real `.rtf` file.** Confirmed by direct reproduction: piping `rtf_body() |> rtf_colheader() |> ... |> write_rtf(file = "x.rtf")` (no `rtf_encode()`) produced a 59-byte ASCII file containing only the cell text with no `{\rtf1` header and no formatting — R reports success (`file.exists()` is `TRUE`, no condition raised) even though the file is not usable as an RTF deliverable. Adding `rtf_encode()` immediately before `write_rtf()` produced a proper ~4KB file starting with `{\rtf1\ansi`. Because both paths "succeed" with no error, verification (§5) must check the file's actual bytes, not just that the R call returned without raising a condition. The same silent dump results from passing `write_rtf()` anything else that is not `rtf_encode()` output, such as the JSON payload list: `write_rtf()` only pastes its input into a file. `render_ard_rtf()` performs the byte check itself and stops when the file is not RTF.

## 5. Verification (add to every skill's Step 9/10 checklist)

- [ ] `tfls/{tfl_id}.rtf` exists after the R program runs.
- [ ] The file starts with `{\rtf1` (read the first bytes, e.g. `readLines(rtf_path, n = 1)` or `readBin(rtf_path, "raw", 20)`) — a file that instead starts with plain row text means `rtf_encode()` was omitted (§4).
- [ ] The file size is on the order of a few KB, not under ~200 bytes — a suspiciously tiny file is the same missing-`rtf_encode()` symptom.
- [ ] The program renders with `render_ard_rtf()` copied verbatim (§3), not with a hand-built r2rtf pipeline or a direct `write_rtf()` call.
- [ ] The rendered table has **no vertical rules** between columns anywhere — header, body, or footnote (§9). A stray vertical line means one of the three calls is missing `border_left = NULL, border_right = NULL`.
- [ ] The first column's values (row labels) are **left-justified** while the value columns stay centred (§9).
- [ ] Each analysis item starts its own section with a single horizontal rule above its header row, and the item's name appears **once**, on that header row; the table's own first row carries a `"single"` top border (§9).
- [ ] Neither structural key leaks into the body: no bare integer (`1`, `2`, …) from `ord_group` and no repeated item name from `group` appears as a rendered cell or column (§2).
- [ ] Every group name that appears in `big_n` appears in the rendered column header text, every footnote appears in the footnote block as `(label) text`, and every `(label)` marker in the header or body has its footnote.
- [ ] `protocol_number` appears in the rendered page header.
- [ ] No text containing `_` or `^` (e.g. `protocol_number`, `program_path`, group/column names, row labels) renders as unintended subscript/superscript — see §6. Confirm every text-bearing r2rtf call passes `text_convert = FALSE`.
- [ ] Every free-text field (`tfl_title`, `tfl_number`, `protocol_number`, `analysis_population`, `program_path`, footnote `label`/`text`, group/column names, row labels) was passed through `rtf_escape()` before being handed to r2rtf — see §7.
- [ ] The rendered title shows `tfl_number` (e.g. `"Table 14-2.01"`), never the `tfl_id` file-naming slug (e.g. `"table_14_2_01"`) — see §2.
- [ ] If any field contains non-ASCII characters (Japanese text, Greek letters, `°`, `±`, accented Latin characters), confirm they render correctly and are not garbled/mojibake in the opened RTF file — see §8. Confirm `rtf_escape()` (not a `use_i18n` argument — this project's r2rtf version doesn't expose one) was applied to every free-text field before it reached r2rtf.
- [ ] If `render_ard_rtf()` fails with an "unused argument" error, the installed r2rtf is a version without one of the arguments it uses (it is tested against r2rtf 1.3.1). Report `packageVersion("r2rtf")` to the user rather than editing the function — see §8's note on `use_i18n`.

## 6. Critical Pitfall: `_` and `^` Silently Become Subscript/Superscript

**r2rtf's default `text_convert = TRUE` unconditionally replaces every literal `_` character with the raw RTF control word `\sub` and every `^` with `\super`, with no matching close/reset.** This is a fixed-string substitution (see `r2rtf:::convert()`), not a paired-delimiter syntax — a single `_` anywhere in a string turns on subscript formatting for everything that follows it in that run, it does not require (or respect) a wrapping pair like `_text_`. Because `program_path` values are snake_case with path segments (e.g. `"programs/tfls/table_14_2_01.r"`), and `protocol_number`, `columns` group names, and row labels frequently contain `_` too, **the default behavior silently corrupts the rendered title/header/body/source line of nearly every real TFL** — e.g. `rtf_source(sprintf("Source: %s", ard$program_path))` with the default `text_convert` renders `"Source: programs/tfls/t"` in normal text followed by `"table 14 2 01.r"` in subscript, with no way to turn it back off within that string.

**Fix:** pass `text_convert = FALSE` to every text-bearing r2rtf call (`rtf_page_header()`, `rtf_title()`, `rtf_colheader()`, `rtf_body()`, `rtf_footnote()`, `rtf_source()`) as shown in §2/§3, so `_` and `^` render as literal characters. This also disables `rtf_footnote()`'s built-in `"\n"` → line-break conversion, which is why the reference implementation joins footnotes with the literal RTF control word `"\\line"` instead of `"\n"` — the same raw-RTF-text mechanism `rtf_colheader()`'s group headers already use (§2), which is unaffected by `text_convert` either way since it never goes through `convert()`.

If a specific TFL Spec genuinely requires LaTeX-style superscript/subscript markup (e.g. a unit like `"m^2^"` or a chemical formula), enable `text_convert = TRUE` only for that specific call/column (`rtf_body()`'s `text_convert` accepts a per-column vector) rather than globally — never leave it at its `TRUE` default for identifier-bearing text.

## 7. Critical Pitfall: `\`, `{`, `}` Are RTF's Own Syntax — r2rtf Never Escapes Them

**RTF uses `\` to start every control word and `{`/`}` to delimit every group. A literal one of these characters in user text corrupts the file's structure, and r2rtf provides no automatic escaping for them — this is true regardless of the `text_convert` setting (§6), because `r2rtf:::convert()` only substitutes `_`, `^`, `>=`, `<=`, `\n`, and a few `\pagenumber`-style tokens; it has no entry for a bare `\`, `{`, or `}`.** `rtf_text()` (r2rtf's internal text-to-RTF encoder) simply wraps whatever string it's given between a literal `{` and `}` with no escaping of the contents in between. Concretely:
- A literal `{` or `}` inside `tfl_title`, footnote text, a row label, or any other free-text field unbalances the RTF group nesting — this can silently drop or misplace content, and in the worst case makes Word refuse to open the file.
- A literal `\` (e.g. a Windows-style path accidentally pasted into `program_path`, such as `C:\Users\name\...`) is read by the RTF parser as the start of a control word — `\U`, `\n`, `\a`, etc. — producing garbled, misinterpreted, or dropped text with no error raised anywhere in the R pipeline.

**Fix:** run every free-text field through the `rtf_escape()` helper (§3) before it reaches any r2rtf call — it replaces `\` → `\\`, `{` → `\{`, `}` → `\}` (backslash first, so the backslashes it inserts for `{`/`}` aren't escaped a second time). This applies to `protocol_number`, `tfl_number`, `tfl_title`, `analysis_population`, `program_path`, footnote `label`/`text`, `columns` group names, and every character-typed cell in `rows` — see §2/§3 for exactly where each call is wrapped. Do **not** run `rtf_escape()` over the literal RTF/r2rtf syntax you construct yourself (the `\\line` control word in `header_str`, or the `"|"` column delimiter) — only over the dynamic values interpolated into those templates, otherwise the deliberate `\line` line break gets escaped into inert text.

## 8. Critical Pitfall: Non-ASCII Text (Including Japanese) Renders Garbled — and `use_i18n` Is NOT a Safe Fix

**`write_rtf()` writes the encoded RTF string to disk with a plain `write()` call — it performs no character-encoding conversion.** Any non-ASCII character (Japanese text, Greek letters like `α`/`β`, symbols like `°` or `±`, accented Latin characters, smart quotes, em/en dashes) that reaches `write_rtf()` unconverted is written as raw UTF-8 bytes directly into the `.rtf` file. Standard RTF expects either 7-bit ASCII with `\'hh` codepage escapes or explicit `\uNNNN` Unicode escapes for anything outside that range — a file with raw UTF-8 bytes spliced into an RTF token stream is very likely to render as mojibake (or fail to render at all) in Word and other RTF readers, even though the R pipeline reports success with no error or warning.

**Do NOT pass `use_i18n = TRUE` to fix this.** An earlier version of this skill recommended exactly that, on the assumption that r2rtf's internal `use_i18n` gate (used by its internal text-encoding function) was exposed as a pass-through argument on the public `rtf_title()`/`rtf_colheader()`/`rtf_body()`/`rtf_footnote()`/`rtf_source()`/`rtf_page_header()` functions. **It is not**, at least not in this project's installed r2rtf version — confirmed directly by running `args(rtf_footnote); args(rtf_title); args(rtf_page_header); args(rtf_colheader); args(rtf_body); args(rtf_source)`, none of which list a `use_i18n` parameter. Passing `use_i18n = TRUE` to any of these calls fails with `Error ... unused argument (use_i18n = TRUE)` — a hard R error, not a silent formatting bug like §6/§7. **This is a general lesson, not just a one-off correction: verify an r2rtf argument exists in the actually-installed version with `args(fn_name)` before relying on it — package documentation online can describe a different version than what's installed (see `renv::status()` if the project appears out of sync).**

**Fix:** `rtf_escape()` (§3) handles non-ASCII characters itself, independent of any r2rtf argument. After escaping `\`/`{`/`}` (§7), it encodes every remaining character with a Unicode code point ≥ 128 as a literal RTF Unicode escape sequence `\uc1\uNNNN?` — this is a local reimplementation of the same logic r2rtf's own (internal, version-fragile) `utf8Tortf()` uses, so it doesn't depend on r2rtf exposing any particular argument at all. Because this happens before the text ever reaches r2rtf, every text-bearing call in §2/§3 only ever needs `text_convert = FALSE` — no `use_i18n` argument anywhere.

## 9. Table Design Settings (borders, justification, sectioning)

These are this project's standing design choices, built into `render_ard_rtf()` (§3). Column widths and page orientation are its arguments; any other change a Shell calls for is a question for the user, since the function is shared by every table.

| Setting | Where | Effect |
|---|---|---|
| `border_left = NULL, border_right = NULL` | `rtf_colheader()`, `rtf_body()`, `rtf_footnote()` | Removes the vertical rules r2rtf draws between columns. All three calls need it — setting it on `rtf_body()` alone leaves the header and footnote boxed. |
| `text_justification = c("l", rep("c", length(ard$columns) - 1))` | `rtf_body()` | Left-justifies the first column (the row labels), centres every value column. One element per column of `tbl`. |
| `text_justification = "l"` | `rtf_page_header()`, `rtf_source()` | Single value, not a per-column vector — these calls render one line of text, not a table row. Flushes the protocol number and the source line to the left margin. |
| `border_top = border_top_mat` | `rtf_body()` | A `nrow(tbl)` × `ncol(tbl)` character matrix, `""` (no rule) everywhere except the first row of each analysis item, where it is `"single"` — so the sections read apart without ruling every row. Built from `!duplicated(rows_df$group)` before `group` is dropped, which works because each item's rows are contiguous. |
| `border_first = "single"` | `rtf_body()` | Draws the table's own top line, independent of the per-row matrix above. |

**Sections come from the header rows and the top rule, not from r2rtf's grouping arguments.** The R-generation skills give every analysis item a header row carrying its name (and its p-value), and `border_top_mat` rules the top of each item. `rtf_body(page_by = "group", pageby_row = "first_row", new_page = FALSE)`, used by earlier versions, renders byte-for-byte the same table on r2rtf 1.3.1, so it is left out; `subline_by` must never be used, as it renders one page per distinct value (confirmed on a real render: a two-item demographics table came out as one page per item).

All arguments `render_ard_rtf()` passes exist in r2rtf 1.3.1, where `test/skill/table-helpers.test.r` renders a sample table and checks the result.
